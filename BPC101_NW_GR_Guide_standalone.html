EXECUTIVE SUMMARY

연결 로직을 속성·룰 테이블·스크립트에 분산 구현한 OLAP 도구

GR 컨설턴트에게 BPC는 전환 고객의 설계 의도를 역추적하는 지도입니다.

구조 · 연결 로직의 3층 분산

Dimension Property(RATETYPE, DATASRC_TYPE, FLOW_TYPE 등) + Business Rule Table + Script Logic(LGF)에 로직이 흩어져 있어, 화면 하나로 전체 로직을 파악할 수 없습니다.

범위·지분 · Ownership Manager

별도 Ownership 모델에 Category·Time·Group별 METHOD·POWN·PCON·PCTRL을 저장하고 Direct/Group Share 자동계산을 제공합니다. GR 표준에는 동등 기능이 없어 재설계 대상입니다.

실행·통제 · 증분연결·Controls·Work Status·BPF

증분(Incremental) 연결, 4단계 Control Level, Bottom-up 잠금, BPF 워크플로가 결산 거버넌스를 구성합니다. GR은 Data/Consolidation Monitor 태스크 중심입니다.

전환 시점 · 유지보수 일정

BPC 10.1 NW(standalone) Mainstream 유지보수는 2027-12-31까지, 선택적 연장은 2030년 말까지로 공지되었습니다(SAP 블로그, 2023.01). 고객 버전별로 PAM 재확인이 필요합니다.

Insight · BPC 고객 진단의 첫 질문은 “Standard인가 Embedded인가”입니다

SAP Fact문서·SAP 공식 근거

  • Standard는 10.0 기능 전체, Embedded는 HANA 기반 BW-PAK 통합 구성 (p.5)
  • Embedded Task Sequence의 “Enable Data Submit Check”는 S/4HANA 리포트로 드릴다운 (p.227, Note 2375986)
  • 10.1 NW standalone Mainstream 2027-12-31, 선택적 연장 2030년 말 (SAP 블로그 2023.01)

Interpretation컨설턴트 해석

  • Standard 고객의 로직은 웹 설정·LGF에, Embedded 고객의 로직은 BW 객체·속성 매핑에 있어 수집 경로가 다릅니다.
  • Embedded의 Task×Entity 실행 매트릭스는 GR 모니터와 구조적으로 유사해 사용자 전환 저항이 상대적으로 낮을 것으로 판단합니다.
  • BPC는 원장 데이터를 복사·적재해 연결하고, GR은 ACDOCA→ACDOCU 원장 연계 구조라는 점이 근본적 차이입니다.

ProposalGR 프로젝트 적용 제안

  • 진단 1단계: connType·모델 유형·Script Logic 사용 여부로 구성을 판별
  • Standard는 LGF·Rule Table 전수, Embedded는 BW InfoProvider·속성 매핑표 수집을 견적 전제로 명시
  • 유지보수 일정은 SAP PAM으로 재확인 후 제안서에 인용

확인 퀴즈

Q1. Embedded 구성에서 사용할 수 없는 계산 수단은?

Script Logic과 Member Formula는 Standard 전용입니다 (p.228).

Q2. Embedded 환경으로 직접 로그온할 때 connType 값은?

Standard는 classic, Embedded는 pak입니다 (p.6).

Insight · DataSrc 체계의 “의미 매핑”이 전환의 첫 산출물입니다

SAP Fact문서·SAP 공식 근거

  • DATASRC_TYPE·IS_CONSOL·IS_CONVERTED 조합이 환산·연결·이월 대상을 결정 (p.193–194)
  • FLOW_TYPE OPENING·CLOSING·VARSCP 멤버는 필수 (p.197)
  • Ownership 모델에는 G만, Consolidation 모델에는 R과 G를 함께 지정 (p.137, 154)

Interpretation컨설턴트 해석

  • GR은 Posting Level·Document Type이 표준으로 고정되지만, BPC DataSrc는 고객마다 설계가 달라 매핑 난이도 편차가 큽니다.
  • Group·Currency 통합 차원은 7.5 이관 이력의 신호로, 레거시 로직 비중이 높을 가능성이 있습니다.
  • Flow 미사용 고객은 증감표를 Account로 처리했을 가능성이 높아 Subitem 설계가 신규 작업이 됩니다.

ProposalGR 프로젝트 적용 제안

  • 산출물 1: Dimension × Property 인벤토리 (속성값 분포 포함)
  • 산출물 2: DataSrc → Posting Level/Document Type, FLOW_TYPE → Subitem 매핑표
  • Embedded 고객은 BW 속성 매핑 화면을 같은 인벤토리 양식으로 정규화

확인 퀴즈

Q1. Account의 RATETYPE이 공란이면?

RATETYPE이 비어 있으면 매칭되는 환산 룰이 없어 환산되지 않습니다 (p.190).

Q2. Ownership 모델에 지정하는 차원 조합으로 옳은 것은?

Ownership 모델에는 G만 지정하며, R과 G를 같은 Ownership 모델에 동시에 둘 수 없습니다 (p.137).

Business Rule

  • CURR_CONVERSION, US_ELIM, COPYOPENING, ICDATA, ICBOOKING

BAdI (ABAP)

  • *START_BADI

적용 규칙 상세
  • Manager = 부모 멤버의 Owner. 최상위 멤버는 자기 Manager를 겸합니다.
  • Owner는 연속 상태로만 이동하며 Manager 상태를 건너뛸 수 없습니다. Manager는 순서와 무관하게 이동하고 On All Descendants로 하위에 일괄 적용합니다.
  • Bottom-up: 부모 상태는 자식 최저 상태를 넘을 수 없고, 부모가 Locked면 자식을 해제할 수 없습니다.
  • 상태 순서 변경·삭제 시 모든 잠금이 삭제됩니다. Embedded는 잠금 차원 1~14개(기본 5).
  • “Journal Only” 패턴: Submitted 이후 Manager가 Journal Only로 바꾸면 입력 스케줄·DM은 막고 저널만 허용합니다. (p.374)
