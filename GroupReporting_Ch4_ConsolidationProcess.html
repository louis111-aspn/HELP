Consolidation Process 개요 & Consolidation Monitor

Consolidation Monitor (신버전, App ID F7271)

Data Monitor에서 데이터를 수집·준비한 이후, Consolidation Monitor에서 이 데이터를 실제로 연결 처리합니다. 최신 Fiori 기반 UI로 필터링 등 향상된 조작이 가능하며, 대부분의 태스크는 자동 실행 대상입니다. 필터 조건을 입력한 뒤 전체 태스크를 한 번에 실행(Full Consolidation)하거나, 필요한 태스크만 선택해 실행할 수 있습니다. 실행 결과는 Task Logs / Task Jobs 앱에서 확인합니다.

💡 실무 인사이트 · 표준 지원 수준

Full Consolidation 1-click 실행은 편의 기능이지, 순서를 알아서 판단해주는 기능이 아닙니다. 시스템은 Define Task Group에 정의된 태스크 순서를 그대로 따르며, 마일스톤 태스크에서 실행이 멈추지 않는다는 점도 유의해야 합니다. 즉 선행 태스크 순서 설정이 정확해야 Full Consolidation이 의도한 대로 동작합니다.

Process Year Period — 분기·계획 단위 처리

기본적으로 Consolidation Monitor는 월 단위(Fiscal Year Period = Process Year Period)로 동작하지만, 여러 회계기간을 하나의 Process Year Period로 묶으면 분기 단위나 계획 단위 처리도 가능합니다. 이를 위해서는 사전에 Define Process Period Cycles와 Assign Process Period Cycles(버전별 할당) 설정이 필요합니다.

주의 — Process Period Cycle 구성은 프로젝트 설계 영역입니다. 분기 단위 연결이 필요하다고 해서 자동으로 지원되는 것이 아니라, 사전에 Cycle을 정의하고 버전에 할당해야 사용할 수 있습니다.

Monitor Layout & 신/구버전 병행 금지

Consolidation Monitor는 Data Monitor와 유사하게 조직 그룹(Consolidation Group) 축을 세로로 배열해 태스크 상태를 보여줍니다. SAP는 Consolidation Monitor(신버전)과 (구버전)을 혼용하지 말 것을 권고하는데, 두 앱을 오가며 사용할 경우 데이터 불일치가 발생할 수 있기 때문입니다. 단, 일부 태스크(예: Calculate Group Shares %(PL30), Preparation Consolidation Group Change, 두 종류의 IC Elimination)의 로그는 구버전에서만 조회 가능하다는 제약이 남아 있습니다.

CHAPTER 02

자동전기 규칙 (Automatic Posting Rules)

연결결산에서 반복되는 저널 전기(내부거래 소거 등)를 자동화하려면, 그 전에 규칙이 정확히 구성되어 있어야 합니다.

Manage Rules for Automatic Postings

이 앱을 통해 전기 규칙을 구성하면, Interunit(Intercompany) Elimination과 같은 반복적인 저널 전기를 자동화할 수 있습니다. 규칙 구성 및 설정 이후, Consolidation Monitor에서 해당 태스크를 실행하면 자동전기가 수행됩니다.

💡 표준 지원 수준

자동전기는 "룰이 있으니 시스템이 알아서 판단해서 전기한다"는 의미가 아닙니다. Manage Rules for Automatic Postings에서 규칙이 사전에 정확히 구성되어 있어야만, Consolidation Monitor 실행 시 그 규칙대로 저널이 자동 생성됩니다.

Display Logs for Automatic Postings (App ID F8345)

자동전기 태스크를 모니터에서 실행하면 로그가 함께 생성됩니다. 로그는 Consolidation Unit 단위의 전체 결과와, Messages / Items 탭에서의 세부 내역을 보여줍니다.

  • Overall Result — Consolidation Group 행이 그룹 전체의 오류·경고를 표시하고, 그 아래 각 Consolidation Unit 행이 개별 결과를 표시
  • Messages 탭 — 태스크 실행 중 발생한 메시지 상세
  • Items 탭 — 실제 생성된 전표 항목 상세

로그 조회에는 SAP_FIN_BC_CCON_CNFPRLS_PC(Posting Rules Configuration) 또는 SAP_FIN_BC_CCON_READ_PC(Read-only) 비즈니스 카탈로그가 필요합니다.

주의 · 일반화 금지 — 로그는 실행 결과에 대한 사후 검증 도구입니다. 규칙 자체의 설계 오류(예: 잘못된 계정 매핑)는 로그가 대신 잡아주지 않으며, Manage Rules for Automatic Postings 단계에서 미리 검증되어야 합니다.

CHAPTER 03

Interunit Elimination — 세 가지 방식 비교

그룹 내부거래(매출·매입, 채권·채무 등)를 소거한다는 목적은 같지만, SAP GR은 이를 구현하는 세 가지 서로 다른 메커니즘을 표준으로 제공합니다.

방식 A vs 방식 B vs 방식 C

방식 A · Reclassification 기반

  • 하나의 계정과목(FS Item)에서 다른 계정과목으로 값을 이전(Reversed sign 사용)
  • Reclassification Method가 Document Type과 함께 Reclassification Task에 연결
  • Posting Level 구성에 따라 여러 소거 유형에 활용
  • Data Monitor 안에서도 실행 가능

방식 B · ICMR Posting Rules 기반

  • Define Posting Rules 앱으로 정의한 전기규칙으로 소거 실행
  • 소거차이를 거래차이 / 환산차이 / 보류항목(WSL) 등으로 세분화
  • 차이 사유는 매칭 시 부여된 Reason Code로 추가 설명 가능
  • File 3(ICMR 매칭·조정)의 매칭 결과를 전제로 동작

방식 C · Automatic Posting Rule 기반

  • Manage Rules for Automatic Postings에 정의된 룰(S2_01/02/03)로 소거 실행
  • ICMR 매칭을 전제하지 않음 — 파트너 유닛 breakdown 보고데이터가 곧 소거의 소스 데이터
  • 판매·매입 유닛이 동일 연결그룹에 포함되어 있어야 자동소거 대상이 됨
  • Consolidation Monitor의 태스크 S20IC로 실행

방식 A 실전 예시 — 재고 미실현이익 소거

그룹 내 매입법인(Buying Unit)이 판매법인(Selling Unit)으로부터 매입한 재고를 기말에 보유하고 있는 경우, 그 안에 포함된 미실현이익을 소거해야 합니다. 매입법인과 판매법인 각각의 보고 데이터를 기반으로, Reclassification 태스크가 Other Expenses ↔ Other Revenue 등 지정된 FS Item 사이에서 트리거 값을 재분류하는 저널을 생성합니다.

방식 B 실전 개요 — Reconciliation 이후의 소거 실행

ICMR(Intercompany Matching and Reconciliation)에서 문서 매칭이 완료되면, 그 매칭 결과를 기반으로 소거 태스크가 실행됩니다. 대표적인 처리 패턴은 다음과 같습니다.

  • P&L 소거(연내) — 같은 회계연도 안에서 발생·매칭·소거가 완료되는 표준 케이스
  • BS 소거(연도 이월) — 채권·채무 등 잔액성 항목이 회계연도를 넘어 이월되는 케이스로, Sub-item으로 소거차이를 구분해 원 FS Item 위에 기록
  • Reconciliation Close 연동 — Manage Reconciliation Close 앱에서 유닛 쌍(Pair)의 조정을 종료(Close)하면 이후 신규 전표는 매칭 로직을 다시 타지 않고 그대로 편입됨

방식 C 실전 개요 — Automatic Posting Rule 기반 소거 (2608 업데이트)

태스크 S20IC(Intercompany Elimination)에 룰그룹 S2_01(Intercompany Elimination)이 배정되어 있으며, 아래 6개 룰로 구성됩니다.

룰대상
S2_01_0101Elim. Interco. Sales — 내부매출 소거
S2_01_0102Elim. Interco. Op. I&E — 영업 수익·비용 소거
S2_01_0103Elim. Interco. Fin. I&E — 금융 수익·비용 소거
S2_01_0104Elim. Interco. Profit in Inv. — 재고 내 미실현이익 소거
S2_02_0101Elim. Interco. Div. — 그룹 내 배당 소거
S2_03_0101Elim. Interco. A&L — 자산·부채(채권·채무) 소거

예를 들어 판매유닛이 파트너 유닛 breakdown으로 매출 1,000을 보고하면, 이 값이 소스 데이터가 되어 매입유닛의 재고 변동 계정에 동일 금액(1,000)의 대응 소거 분개가 자동 생성됩니다. 채권·채무 소거의 경우 판매·매입 유닛의 보고금액이 서로 다르면(예: 1,000 vs 950) 차이는 Intercompany Difference FS Item으로 별도 분석됩니다.

방식 A·B와의 경계 — 방식 C는 방식 B(ICMR Posting Rules)의 대체재가 아닙니다. 방식 C는 매칭·조정 없이 파트너 유닛 breakdown 보고데이터만으로 곧바로 소거를 실행하는 단순 케이스에 적합하며, 매칭 차이·환산차이 등 세분화된 예외 처리가 필요한 경우에는 방식 B(ICMR 기반)가 필요합니다.
💡 Delta / Next-Year Processing

ICMR 기반 소거는 YTD(누계) 기준으로 실행되지만 실제 전기는 델타(증분) 방식이라, 특정 이전 기간의 데이터가 바뀌면 그 이후 기간을 순서대로 다시 실행해야 정확한 결과가 나옵니다. 또한 연도의 마지막 기간에 실행한 소거는 다음 연도로 자동 반제(Auto Reverse)되지 않으므로, 회계연도 전환 시점의 처리 방식을 별도로 확인해야 합니다.

CHAPTER 04

Consolidation of Investments (C/I) — 두 가지 방식

C/I는 투자자의 투자계정과 피투자회사 자본을 상계하는 자본연결 처리입니다. SAP GR은 이를 자동화하는 서로 다른 두 가지 룰 체계를 제공합니다.

활성화 전제조건 (공통)

어느 방식이든 Assign Task Group to Dimension 구성 활동에서 사용할 룰 체계를 지정해야 하며, 무엇보다 투자지분율(Investment Share)과 그룹지분율(Group Share)이 Master Data로서 정확히 유지되어 있어야 합니다.

프레임 재확인

SAP GR은 IFRS 판단을 대신 내려주는 추론 엔진이 아니라, 사전 구성된 Master Data(지분율, Ownership 정보)를 기반으로 정해진 로직을 실행하는 연결 엔진입니다. C/I 자동화의 품질은 어느 방식을 쓰든 결국 지분 Master Data의 정확도에 달려 있습니다.

방식 A vs 방식 B

방식 A · Reclassification 룰셋 기반

  • Method Sequence Step에 percentage selection 조건을 정의해 시나리오별 Method(S2101, SMC01/SMC02, S2181, S2030 등)로 실행
  • Calculate Group Shares(PL30) 태스크로 그룹지분율을 산출한 뒤 Method에 적용
  • Ch.5(PCC)의 그룹구조 변경 조정과 동일한 체계에서 동작

방식 B · Automatic Posting Rule 기반 (2608 신규)

  • 룰그룹 S3_01 산하에 구매법·지분법별로 세분화된 룰 범위(S31_10/20_xxx)로 실행
  • Manage Rules for Automatic Postings에서 구성 — Ch.3 방식 C(내부거래상계 자동전기)와 같은 성격의 새로운 선택지
  • Document Type(3D/3E/3F/3X/3Z)으로 FS Item 변경 성격별 추적성 확보

스탠딩 룰 · 자동 결정 아님 — 어떤 Consolidation Method가 적용되는지는 위 시나리오 표 하나로 자동 결정되지 않습니다. 실제로는 Ownership Manager의 구성과 프로젝트별 설계에 따라 방법이 정해지며, 표는 "각 시나리오에 대응하는 표준 Method가 존재한다"는 사실을 보여줄 뿐입니다.

CHAPTER 05

그룹구조 변경 조정 & 지분율 계산

연결그룹의 구성이 바뀌면(유닛 편입·이탈, 방법 변경) 이미 반영된 데이터를 소급 조정해야 합니다. PCC와 Group Shares 계산이 이 역할을 맡습니다.

Preparation for Consolidation Group Changes (PCC)

Consolidation Unit이 그룹에 편입되거나, 그룹에서 이탈하거나, 연결방법이 바뀔 때, 보고데이터·표준화데이터·소거데이터를 조정하는 태스크입니다. 조정분개의 내용은 적용 방법에 따라 다릅니다.

  • 구매법(Purchase Method) 조정 — 편입·이탈·방법변경 시점 기준 조정 전기 유형이 별도로 정의
  • 지분법(Equity Method) 조정 — 구매법과 다른 조정 로직 적용
  • 통계적 FS Item에도 동일 로직이 적용되지만, 취득 전·처분 후 등 특정 조건에서만 유효

조정분개는 원래 전기가 이루어진 Posting Level과 연계된 별도의 Posting Level에서 생성됩니다. 시스템은 이를 Record Type으로 구분해 관리하며, 어떤 시나리오(편입/이탈/방법변경)로 인해 생성된 전기인지 식별할 수 있게 합니다.

💡 Next Steps

PCC 실행 이후에는 해당 태스크를 Block(잠금) 처리해 재실행으로 인한 중복 조정을 방지할 수 있습니다.

Calculate Group Shares (PL30)

방식 A(Reclassification 룰셋 기반) C/I 시나리오에서 그룹지분율을 산출하는 태스크입니다. Method Sequence Step의 percentage selection에서 입력한 지분율 선택 기준을 바탕으로, 시스템이 해당 선택 조건에 맞는 그룹지분율 값을 추출합니다.

일반화 주의

Group Shares 계산 역시 "시스템이 지분구조를 스스로 판단"하는 것이 아니라, Method Sequence Step에 입력된 percentage selection 조건이 정확해야 의미 있는 결과가 나옵니다. Ch.04의 프레임과 동일하게, GR은 사전 구성된 Master Data 위에서 정해진 로직을 실행할 뿐입니다.

CHAPTER 06

수동분개(Group Journal Entries) & 최종 검증

자동전기로 커버되지 않는 조정(이연법인세 등)은 수동으로 전기하며, 조직에 따라 워크플로 승인을 거칠 수 있습니다. 마지막 관문은 Consolidated Data Validation입니다.

Post Group Journal Entries (App ID F2971)

보고데이터 조정, 표준화 전기, 연결 전기 등을 수동으로 생성하는 앱입니다. Interunit Elimination이나 C/I처럼 자동전기로 처리되는 태스크가 있는 반면, 이 앱은 그 범위 밖의 예외적 조정(대표적으로 이연법인세 반영)에 사용됩니다. 버전·회계연도·전기기간·전표유형을 선택해 Journal Entry를 작성하며, Check 기능으로 전기 전에 정합성을 검증하고, Balance 버튼으로 선택된 라인 항목의 금액을 자동 계산해 채울 수 있습니다.

  • 기존 Journal Entry를 템플릿으로 활용해 신규 항목 생성 가능
  • 파일 업로드 또는 URL 형태로 근거 문서 첨부 가능
  • 개별 전기 반제(Reverse) 또는 Mass Reversal 앱을 통한 일괄 반제 지원
  • 전기 전 Draft로 저장 후 추후 완료 가능

Import Group Journal Entries (App ID F3073)

다건의 수동분개를 파일 업로드로 한 번에 처리하는 앱입니다. 전표유형(표준화 조정, 양방향 소거, 그룹종속 조정 등)에 맞는 템플릿을 다운로드해 Header Data / Line Items를 입력하고, Check로 검증 후 Post로 최종 반영합니다. 커스텀 필드가 정의되어 있다면 템플릿에 자동 포함되어 표준 필드와 동일하게 처리됩니다.

Display Group Journal Entries — With Reporting Logic (App ID F3831)

모든 Posting Level(00~30)의 전표 라인 항목을 조회하는 앱입니다. Consolidation Unit/Group, 프로핏센터·세그먼트 계층 등으로 필터링할 수 있고, Universal Journal을 통해 통합 관리되는 문서는 개별 문서번호 링크를 통해 Manage Journal Entries(Old Version)로 드릴다운해 원 전표까지 확인할 수 있습니다.

주의 — 드릴다운 기능은 Manage Journal Entries(Old Version) 앱과의 연동이 전제이며, 해당 비즈니스 카탈로그를 Maintain Business Roles에서 명시적으로 역할에 추가해야 사용할 수 있습니다.

Consolidated Data Validation — 최종 관문
