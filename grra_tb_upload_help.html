PG-DC-0020

Non-SAP 시산표 업로드 및 전송

Non-SAP 법인의 시산(TB) 데이터를 엑셀 파일로 업로드하고, G/L 계정 코드와 재무제표 항목(FS Item) 간의 매핑을 적용하여 저장한 뒤 SAP Group Reporting(GR) 시스템에 전송하는 프로그램입니다. 잔액 검증, 계정 점검, 테스트 실행을 거쳐 최종 전표를 생성합니다.

1

프로그램 실행 및 초기 화면

프로그램 실행 시 파일 업로드 화면이 바로 표시됩니다.

PG-DC-0010과 달리 별도의 조회 조건 없이 엑셀 파일 업로드 중심으로 운영됩니다. TB 데이터는 엑셀 파일을 통해 일괄 업로드되므로 조회 조건이 없습니다.

화면 구성 요소

📥 템플릿 다운로드

업로드용 표준 엑셀 파일(TB_Upload.xlsx)을 다운로드합니다.

📂 찾아보기 (파일 선택)

업로드할 엑셀 파일을 선택합니다. 파일 형식: xlsx (기본값)

▶️ 실행

선택한 파일을 시스템에 업로드하고 데이터를 수집합니다. 팝업에서 확인을 클릭하여 진행합니다.

⚖️ 잔액 검증

로컬통화금액·그룹통화금액·거래통화금액의 잔액 검증 결과를 그리드 위에 표시합니다.

🔍 계정 점검

업로드된 G/L 계정의 매핑 여부를 확인합니다. 미매핑 계정 발견 시 계정매핑 버튼이 활성화됩니다.

🔗 계정 매핑

PG-DC-0010 프로그램으로 이동하여 미매핑 계정을 처리합니다.

계정 점검 후 미매핑 계정 존재 시 활성화

🧪 테스트 실행

GR 시스템에 실제 전표를 생성하기 전 테스트를 수행합니다. 성공/실패 결과를 확인합니다.

📄 전표 생성

테스트 성공 후 GR 시스템에 실제 전표를 생성(전송)합니다.

테스트 성공 후 활성화

💾 저장

현재 작업 내용을 저장합니다.

📨 제출

저장한 작업을 승인자에게 제출합니다.

✅ 승인

승인자가 제출된 내용을 승인 또는 반려 처리합니다.

승인 로직은 추후 개발 예정

📋 작업관리로그

작업 내역을 기록하고 상태 로그를 확인합니다.

2

템플릿 다운로드

업로드 전 반드시 표준 템플릿(TB_Upload.xlsx)을 사용해야 합니다.
  • 1
    템플릿 다운로드 버튼 클릭
    초기 화면 상단의 템플릿 다운로드 버튼을 클릭하면 TB_Upload.xlsx 파일이 다운로드됩니다.
  • 2
    파일에 데이터 입력
    다운로드된 템플릿의 지정된 열에 시산표 데이터를 입력합니다. 필수 필드와 선택 필드를 구분하여 입력합니다. (아래 업로드 템플릿 필드 명세 참조)
📌 파일명 안내: 업로드 템플릿 파일명은 TB_Upload.xlsx입니다. (구 파일명: 모회사TB_FLEXIBLE_GR)

파라미터값설명

3

파일 업로드 (임포트)

작성 완료된 엑셀 파일을 시스템에 업로드합니다.
  • 1
    찾아보기 클릭 → 파일 선택
    찾아보기 버튼을 클릭하여 업로드할 TB_Upload.xlsx 파일을 선택합니다. 파일 탐색기 창이 열립니다.
  • 2
    실행 클릭 → 팝업 확인
    실행 버튼을 클릭하면 확인 팝업이 나타납니다. 확인을 클릭하면 파일 데이터가 시스템에 적재되고 그리드에 결과가 표시됩니다.
  • 3
    업로드 결과 확인
    업로드된 데이터가 그리드에 표시됩니다. 계정 오류나 금액 문제가 있으면 경고/문제점이 함께 표시됩니다. 잔액 검증도 업로드와 동시에 실행됩니다.
⚠ 기간 마감 주의: 데이터 모니터에서 해당 기간이 마감(Close) 상태인 경우, 업로드 시 오류 메시지가 반환됩니다. 기간 오픈 여부를 사전에 확인하세요.

잔액 검증

업로드된 시산 데이터의 통화별 잔액이 일치하는지 검증합니다.

업로드와 동시에 잔액 검증이 자동 실행되며, 잔액 검증 버튼을 통해 수동으로 재실행할 수도 있습니다. 검증 결과는 그리드 위에 표시됩니다.

검증 대상 통화 금액

🏦
로컬통화금액
HSL (AmountInLocalCurrency)
🌐
그룹통화금액
KSL (AmountInGroupCurrency)
💱
거래통화금액
TSL (AmountInTransactionCurrency)
📌 잔액 검증 원칙: 로컬통화·그룹통화·거래통화 금액 3가지 모두 잔액 점검이 필요합니다. 거래통화(RTCUR)가 입력된 경우 거래통화금액(TSL)도 반드시 함께 입력되어야 합니다.
5

계정 점검 및 계정 매핑

업로드된 G/L 계정이 재무제표 항목과 올바르게 매핑되어 있는지 확인합니다.
  • 1
    계정 점검 버튼 클릭
    업로드 후 계정 점검 버튼을 클릭하여 연결단위의 계정과목(업로드)과 연결계정과목표(Y1) 간 매핑 여부를 확인합니다.
  • 2
    미매핑 계정 확인
    매핑되지 않은 계정이 발견되면 해당 내역이 표시되고 계정 매핑 버튼이 활성화됩니다.

미매핑 계정 처리 흐름 (PG-DC-0010 연동)

▶
현재 화면 (PG-DC-0020)
계정 점검 결과 → 미매핑 계정 발견 → 계정 매핑 버튼 클릭
→
매핑 프로그램으로 이동 PG-DC-0010
해당 연결단위 페이지로 자동 이동
→
PG-DC-0010에서 편집
편집 버튼 클릭 → 미매핑 계정 추가/수정 → 저장
→
PG-DC-0020으로 복귀
계정 점검 버튼을 다시 클릭하여 매핑 완료 여부 재확인
📌 매핑 유효기간 적용: PG-DC-0010의 효력 시작일~종료일 기준으로, 업로드 시점에 유효한 매핑 내역이 자동 적용되어 G/L 계정을 FS Item에 매핑합니다.
6

테스트 실행

GR 시스템에 실제 전표를 생성하기 전 시뮬레이션을 수행합니다.
  • 1
    테스트 실행 버튼 클릭
    잔액 검증과 계정 점검이 완료된 후 테스트 실행 버튼을 클릭합니다.
  • 2
    결과 확인
    테스트 실행 결과로 성공 또는 실패가 표시됩니다. 실패 시 오류 내용을 확인하고 데이터를 수정한 후 재시도합니다.
⚠ 테스트 실행 목적: 테스트 실행은 실제 GR 전표를 생성하지 않습니다. 데이터의 유효성과 GR 시스템 처리 가능 여부를 사전에 검증하는 단계입니다. 테스트 성공 후에만 전표 생성이 가능합니다.
7

전표 생성 (GR 전송)

테스트 성공 후 GR 시스템에 실제 전표를 생성하여 연결결산에 반영합니다.
  • 1
    전표 생성 버튼 클릭
    테스트 성공 후 활성화된 전표 생성 버튼을 클릭합니다.
  • 2
    GR 시스템 전송 및 결과 확인
    시스템이 SAP Group Reporting에 전표를 생성합니다. 성공 시 승인전표번호(DOCNR)가 생성되어 마스터 테이블(ZGRTUPL01)에 기록됩니다.
⚠ 재업로드 시 주의: 동일 법인/기간에 대해 재업로드 시 UPDATEMODE 설정에 따라 기존 데이터 처리 방식이 달라집니다. 아래 업데이트 모드 설명을 반드시 확인하세요.
8

저장 / 제출 / 승인

작업 결과를 저장하고 승인 워크플로우를 진행합니다.
💾 저장

계정 매핑 작업이 완료되면 저장합니다. 작업 상태(WFSTATUS)가 업데이트됩니다.

📨 제출

저장한 작업을 승인자에게 제출합니다. 작업상태로그(ZGRTUPL02)에 이력이 기록됩니다.

✅ 승인 / 반려

승인자는 제출된 내용을 검토 후 승인 또는 반려 처리합니다.

승인 태우는 로직은 추후 개발 예정

📋 작업관리로그

작업 이력(상태, 연결단위, 매핑ID, 개정, 처리일시, 처리자 등)을 기록하고 조회합니다.

·

업데이트 모드 (UPDATEMODE)

파일 업로드 시 기존 데이터를 어떻게 처리할지 결정하는 핵심 파라미터입니다.
1
Delete
전체 대체
동일한 Version/Period/Consolidation Unit/Document Type 조합의 기존 데이터를 무효화하고 새 데이터로 대체합니다. 물리적 삭제 없이 이전 데이터와의 차이(delta)만 신규 레코드로 생성합니다.
2
Overwrite
일치 항목 덮어쓰기
동일한 FS Item과 모든 Subassignment(손익센터, 부문 등)가 일치하는 기존 레코드만 덮어씁니다. 일치하지 않는 다른 레코드는 그대로 유지됩니다.
5
Add (기본값)
단순 추가
업로드된 레코드를 기존 데이터와 무관하게 단순 추가합니다. 완전히 동일한 항목도 중복 레코드가 생성될 수 있으므로 주의가 필요합니다.
⚠ Mode 5 (Add) 주의: 기본값인 Mode 5는 동일 항목에 대해 중복 레코드가 생성될 수 있습니다. 재업로드 시에는 Mode 1(Delete)을 고려하세요.

데이터 검증 로직

업로드 시 시스템이 자동으로 수행하는 유효성 검사 항목입니다.
검증 항목점검 로직예외 처리
필수 필드 입력 RITCLG, RVERS, RYEAR, POPER, RBUNIT, RITEM, ZRACCT, HSL 입력 여부 확인 누락 시 오류 반환 및 업로드 차단
회계연도 / 기간 유효성 RYEAR는 4자리 숫자, POPER는 01~12 범위 확인 범위 초과 시 오류 반환
금액 필드 정합성 HSL, TSL, KSL 등 금액 필드에 숫자 이외 입력 차단 숫자 외 입력 시 오류 반환
