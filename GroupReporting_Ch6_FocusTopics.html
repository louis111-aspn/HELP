CHAPTER 01

Equity Pickup(EPU) — 지분법 평가 조정

Equity Pickup(App ID FINCS_EPU_EXEC)은 지배 Consolidation Unit이 보유한 투자주식을 피투자회사의 최신 지분가치로 재평가하는 조정 프로세스입니다. 투자회사 내부의 연결 시스템에서 처리되며, 그룹 내 모든 투자 체인에 대해 하위에서 상위 방향으로 실행됩니다.

Controlling vs Noncontrolling Parent 판정

EPU 설정에서 Noncontrolling·Controlling 지분율 임계값(threshold)을 정의하면, 시스템은 각 Parent의 직접 소유 비율이 어느 구간에 속하는지에 따라 자동으로 지배관계를 판정합니다. 예를 들어 Noncontrolling 20%·Controlling 50%로 설정하면, 소유 비율이 50% 이상이면 지배 Parent, 20~50%이면 비지배 Parent, 20% 이하이면 EPU를 수행하지 않습니다.

💡 예외 처리 · Force Control Indicator

지분율만으로 실제 지배력을 판단하기 어려운 경우(예: 40% 소유이지만 계약상 지배력 보유), FS Item을 Force Control Indicator로 지정해 특정 수량값(예: 1=지배, -1=비지배)을 리포트하면 지분율 임계값과 무관하게 지배관계를 강제로 override할 수 있습니다.

일반화 주의

Force Control Indicator의 override 기준은 SAP가 자동 판단해주는 것이 아니라, 계약·의결권 구조를 분석한 프로젝트 설계 결정을 시스템에 반영하는 수단일 뿐입니다. "몇 % 이상이면 무조건 지배"라는 식의 일반화된 규칙으로 이해해서는 안 됩니다.

Calculation Approach 1 vs 2

구분Approach 1Approach 2
NCI 표시 방식지배 Parent가 피투자회사 지분 100%를 투자계정에 인식하고, 비지배지분은 별도 NCI FS Item에 분리 계상NCI를 별도 FS Item으로 분리하지 않고, 투자계정 잔액 자체를 순지분(net share) 기준으로 차감 표시
투자계정 잔액총지분 기준순지분 기준

ASPN 예시 — 다단계 투자 체인 (Approach 1)

ASPN Holdings 산하에 ASPN Europe(지배 Parent)이 있고, ASPN Europe은 ASPN Tech 지분 100%, ASPN Energy Korea K300 지분 60%를 보유하며, ASPN Tech는 다시 ASPN Energy Korea K300 지분 10%를 보유하고 있다고 가정합니다(threshold: Noncontrolling 20%·Controlling 50%).

  • ASPN Tech의 K300 지분(10%)은 threshold 이하이므로 EPU 대상에서 제외됩니다.
  • ASPN Europe의 K300 지분(60%)은 threshold 이상이므로 지배 Parent로서 EPU를 수행합니다.
  • EPU 순서는 항상 체인의 최하위(K300)에서 최상위(ASPN Europe) 방향으로 진행되며, ASPN Europe은 K300의 재평가된 지분변동분의 60%를 투자계정에 반영합니다.
스탠딩 룰 · 소스 데이터 범위 — EPU는 원칙적으로 당기 순이익(Net Income)과 기타포괄손익(OCI) 변동분만 반영하며, 전기 이전 이익잉여금은 대상에서 제외됩니다. 소유권 변경이 있었던 경우, 신규 지배회사 인수 이전 시점의 피투자회사 지분가치는 EPU 대상에 포함되지 않습니다.
💡 순환출자(Circular Ownership) 케이스

A가 B의 지분을 보유하고 B도 A의 지분 일부를 보유하는 순환출자 구조에서는, 재평가된 순이익(A', B' 등)이 서로를 참조하는 연립방정식으로 표현됩니다. 예를 들어 A'=100+0.6B', B'=200+0.1A'라는 관계라면 두 식을 대입해 B'≈223.4, A'≈234.0처럼 수렴값을 계산합니다. 시스템은 이 계산을 자동 수행하지만, 대상 FS Item 선택 기준(Net Income·OCI 유형별 규칙)은 사전 구성이 필요합니다.

Reporting & Analysis

EPU 실행 결과는 EPUGroupJournalEntries.xlsx(Group Reporting 반영용)·EPU_GL_JournalEntries.xlsx(General Ledger 반영용)·EPU_LOG_YYYYMMDDnnnn.csv(계산 상세 로그) 세 파일로 로컬에 저장됩니다. Import Group Journal Entries 또는 Upload General Journal Entries 앱으로 업로드한 뒤, Group Data Analysis에서 EPU 반영 재무제표를 조회합니다.

CHAPTER 02

Group Reporting Preparation Ledger 통합

General Ledger 회계 데이터를 별도로 Group Reporting에 다시 전송하지 않고, 회계 원장 자체에 GR 관련 필드를 확장해 직접 연동하는 구조입니다. 데이터를 이중으로 왕복시키지 않는다는 점이 핵심입니다.

기존 방식 대비 이점

  • 세밀한 수준의 재무 데이터에 조기 접근 가능
  • 물류 문서 기반 예측치를 포함한 최신 데이터에 상시 접근
  • 변경분만 릴리스(Delta Release)하여 전체 모드 릴리스로 인한 성능 저하 회피
  • 특수기간(Special Period)으로 별도 릴리스 가능 — 마지막 정기 기간에 합산되는 문제 방지

Define Group Reporting Preparation Ledgers 설정을 통해 Consolidation Group·Posting Level 등 GR 전용 필드가 General Ledger에 추가되며, 이 값들은 Release 태스크 실행 시 사전 정의된 Substitution Rule로 도출되어 회계 쪽에 함께 기록(replication)됩니다.

CHAPTER 03

Custom Sign Convention — 자체 부호 로직

SAP 표준 Sign Logic은 모든 FS Item의 양수 금액을 차변(Debit), 음수 금액을 대변(Credit)으로 해석합니다(예: 수익은 음수로 저장). Custom Sign Convention은 FS Item Type·FS Item 레벨에서 이 해석을 프로젝트 요구에 맞게 재정의할 수 있게 합니다.

설정 절차

1. Global System Settings
Debit/Credit Indicator + Customer-Defined Sign Convention 체크박스 활성화
→
2. Default Sign Convention 정의
Define Default Sign Convention for FS Item Types에서 FS Item Type별 Debit/Credit Item 지정

Debit Item으로 지정하면 양수=차변·음수=대변, Credit Item으로 지정하면 음수=차변·양수=대변으로 해석됩니다. FS Item Type 레벨 기본값은 개별 FS Item 레벨에서 재정의(override)할 수도 있습니다.

스탠딩 룰 · 활성화 시점 제약 — Customer-Defined Sign Convention 기능을 활성화·비활성화하면, 이미 Credit Item으로 설정된 FS Item의 증가·감소 포스팅 해석이 정반대로 뒤바뀝니다. 따라서 이 스위치는 GR에 이미 트랜잭션 데이터가 존재하는 시스템에서는 변경해서는 안 되며, FS Item Type·FS Item 레벨 기본값 점검도 반드시 데이터 발생 이전에 완료해야 합니다.

활성화 시 영향 범위

Custom Sign Convention 활성화는 Release Universal Journal 태스크, GR 핵심 기능, Analytics for Group Reporting, 데이터 수집 앱, SAC 계획 데이터 Import, 수기 그룹 전표 앱, Line Item Validation, Task Logs 등 GR 전반의 처리 로직에 영향을 미칩니다.

일반화 주의 · 비활성화되는 기능

Custom Sign Convention을 활성화하면 SAC로부터의 계획 데이터 Export, Copy Transaction Data(거래 데이터 복사), Mass Reversal(일괄 반제) 세 기능이 비활성화됩니다. "부호 로직만 바뀔 뿐 다른 기능은 그대로"라고 단정해서는 안 됩니다.

CHAPTER 04

Flexible Derivation of Consolidation Units & Partner Units

하나의 Company(회사)를 복수의 Consolidation Unit에 매핑해두고, 회계 포스팅 시점에 Segment·Profit Center 등 추가 기준에 따라 그중 하나를 자동으로 도출(derive)하는 기능입니다. 회사 단위로만 존재하던 조직구조를, 세그먼트별 연결처럼 더 세분화된 기준으로 쪼개고 싶을 때 사용합니다.

전제조건

  • From Year for Group Reporting Preparation Ledger 이후 회계기간에서 작업 중이어야 함(그 이전 기간은 Company와 동일 ID의 Consolidation Unit에 자동 배정됨)
  • Plan Version이 아닌 버전에서 작업 중이어야 함(Plan Version에서는 항상 동일 ID CU에 자동 배정)
  • 동일 회계기간에는 하나의 Consolidation Unit에 하나의 Company만 배정 가능(단, 하나의 Company는 여러 CU에 배정 가능)

3단계 도출 프로세스

1. Company 복수 매핑
Define Consolidation Units / Import Consolidation Master Data
→
2. Substitution Rule 도출
Segment·Profit Center 등 기준으로 CU 하나 선택
→
3. Universal Journal 반영
도출된 CU가 회계 전표에 영구 기록(persist)됨

Trading Partner가 존재하는 포스팅은 CU 도출이 트리거된 직후 Partner Unit 도출도 동일한 3단계 구조로 이어서 실행됩니다.

ASPN 예시 — 세그먼트별 분할 포스팅

ASPN Tech(IT 서비스)가 하나의 Company로 존재하지만, 내부적으로 클라우드 사업부·SI 사업부 두 세그먼트를 각각 별도 Consolidation Unit(ASPN_TECH_CLOUD, ASPN_TECH_SI)으로 연결·보고하고 싶다고 가정합니다. Define Consolidation Units에서 ASPN Tech를 두 CU 모두에 배정한 뒤, Segment 필드를 조건으로 하는 Substitution Rule을 만들면, 회계 전표의 Segment 값에 따라 두 CU 중 하나가 자동 도출됩니다. 이렇게 도출된 CU 기준으로 계층(Hierarchy) 또는 Consolidation Group을 구성하면 세그먼트별 연결·보고가 가능해집니다.

Table Lookup — 다수 CU를 하나의 규칙으로 처리

도출 대상 CU가 많을 경우, CU마다 개별 Substitution Rule을 만드는 대신 Table Lookup 방식을 사용합니다. Custom Business Object로 Lookup Table을 만들어 Company Code·Segment 등을 Key 필드로, Consolidation Unit을 결과 필드로 정의한 뒤, 하나의 Substitution Rule에서 이 테이블을 참조해 여러 CU를 한 번에 도출합니다.

스탠딩 룰 · Lookup Table 정합성 미검증 — Lookup Table 항목을 생성할 때 시스템은 Consolidation Unit Master Data와의 정합성을 자동 검증하지 않습니다. 예를 들어 동일 CU에 서로 다른 Company Code를 매핑하는 모순된 항목을 만들 수 있는데, 이 경우 3단계(Universal Journal 반영) 시점에 정합성이 재검증되어 모순된 CU 값은 초기화(clear)되거나 되돌려집니다. Lookup Table 유지보수 시 Master Data와의 일치 여부를 별도로 확인해야 합니다.

CHAPTER 05

SAP Green Ledger 통합 — 탄소회계 연계

SAP Green Ledger는 여러 입력 채널의 탄소 데이터를 수집·집계해 재무보고와 결합하는 솔루션입니다. Group Reporting과 통합하면 온실가스(GHG) 데이터를 재무제표의 부채 항목으로 반영하고, 분석·감사 리포트에 활용할 수 있습니다.

전제조건 — 계정 및 재무제표 구조

다음 4개의 대차대조표 계정(G/L Account Type: Balance Sheet Accounts)을 생성해야 합니다.

  • Carbon Transition Account
  • GHG Liabilities Account
  • GHG Liabilities Transferred to Customers
  • Retained GHG Liabilities

이 계정들은 Financial Statement Version의 Liabilities and Equity 노드 아래 GHG Liabilities라는 별도 서브노드에 배정합니다.

GHG 관련 추가 필드

Enable Greenhouse Gas Fields in Group Reporting 비즈니스 기능을 활성화하면 GHG Scope, GHG Category, GHG Scope 2 Calculation Method, GHG Energy Classification, Sustainability Mode of Transport 등의 필드가 활성화되어 Group Data Analysis, Define Selections, Post Group Journal Entries 등 기존 GR 앱에서 그대로 사용할 수 있습니다.

Constraints — GHG 관련 필드는 Release Universal Journal 태스크로는 전송되지 않으며, 지분법 기준 투자 처리(Activity-Based Consolidation of Investments)에서도 처리되지 않습니다. 이 두 시나리오에서는 별도 데이터 반영 경로(Data Mapping Job, 수기 입력 등)를 설계해야 합니다.

ASPN 예시 — ASPN Energy Korea(K300)

ASPN Energy Korea(K300)는 그룹 내 에너지·유틸리티 사업부로, 발전·송배전 과정에서 발생하는 온실가스 데이터를 정기적으로 집계해야 하는 특성상 Green Ledger 연동의 적용 대상으로 적합합니다. K300의 Green Ledger 인스턴스에서 JournalEntryEmissions API를 노출하고 GHG Scope·Category 필드를 GR FS Item에 매핑하면, ASPN Holdings 연결 재무제표의 GHG Liabilities 노드에서 K300의 탄소 부채를 다른 계열사(ASPN Tech, ASPN Europe 등)와 동일한 Group Data Analysis 화면으로 조회할 수 있습니다. 다만 이는 SAP 표준 기능 범위 내 구조 설명이며, K300의 실제 배출량·회계처리 세부사항은 별도 검증이 필요합니다.

💡 최신성 확인 필요

Green Ledger 통합은 비교적 최근에 추가된 영역으로 Public Cloud 릴리스별 지원 범위가 달라질 수 있습니다. 프로젝트 적용 전 SAP Road Map Explorer에서 해당 릴리스의 지원 여부를 확인하는 것을 권장합니다.

CHAPTER 06

Ownership-Driven Group Structure Management (2608 업데이트)

2608부터 Manage Consolidation Group Structure 앱이 지분율·통제율 자동계산과 오너십 기반 배정 제안 기능을 함께 제공합니다. Scope(구조배정) → Percentage(지분율) → Method(연결방법 제안)를 하나의 프로세스로 연결하는 신규 워크플로우입니다.

활성화 전제조건

이 기능은 scope item 1SG가 활성화된 2608 이상 릴리스에서 사용 가능합니다. Manage Consolidation Group Structure 앱은 기존의 Unit View / Group View 두 앱을 하나로 통합했습니다.

일반화 주의 · 용어 구분

이 기능은 BPC의 Ownership Manager와는 무관한 GR 네이티브 기능입니다. Manage Consolidation Group Structure 앱 안에서 동작하는 지분 기반 배정 제안 워크플로우이며, Ch.4의 Rule-Based C/I가 전제로 삼는 지분 Master Data 유지와도 별개의 화면·프로세스입니다.

지분율 3단계 수집

  • 직접 소유지분율(Direct Ownership %) — 투자자가 피투자회사에 보유한 지분율
  • 직접 의결권지분율(Direct Voting Rights %) — 소유지분율과 다를 때만 별도 보고(통제력 판단에 영향)
  • 직접 통제지분율(Direct Control %) — 의결권지분율이 소유지분율과 같으면 통제지분율도 소유지분율과 동일

Control Setting 값 +1은 통제를 강제 인정, -1은 통제를 강제로 배제하는 데 사용합니다. 이 값들은 수기 보고 외에, 발행주식수·보유주식수 데이터가 있으면 자동전기 룰로도 산출할 수 있습니다.
